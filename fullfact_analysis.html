🤖 Full Fact AI 기술 파이프라인
공식 문서 + "How we fact check" 페이지 기반 추정
1
클레임 모니터링 (수백만 문장/일)
텍스트, 오디오, 영상 멀티모달 입력 처리. 의회 발언, 뉴스, SNS 실시간 스캔
2
Check-Worthy 클레임 분류
NLP 분류기로 검증 가능한 사실 주장만 선별. 의견/수사적 발언 제외
3
기존 팩트체크 DB 매칭
수천 건의 기존 팩트체크 아티클과 신규 주장을 자동 매칭. 중복 검증 제거
4
Human-in-the-Loop (전문 팩트체커)
AI는 보조 역할. 최종 판단은 반드시 전문 저널리스트·사실확인자가 수행. AI 단독 퍼블리싱 없음
5
팩트체크 퍼블리싱 + 교정 요구
검증 결과 공개. 허위 주장 발화자에게 정정 요구. 미응답 시 공개적 지적
🔬 기술적 특징 분석
멀티모달 처리 (텍스트·오디오·영상)
공식 문서: "우리 AI 도구는 텍스트, 오디오, 영상에서 수백만 문장을 매일 모니터링할 수 있다." → 자체 STT 파이프라인 또는 외부 ASR API 통합 추정
AI 벤치마크 (독립 평가 체계)
GPT, Claude 등 주요 LLM의 팩트체킹 정확도를 공개·감사 가능한 방식으로 측정. 신뢰성 확보를 위한 투명성 전략. 우리 프로젝트에서 신뢰도 스코어링 설계 시 참고 필수
클레임 선별 필터 (Cost Control)
모든 문장이 아닌 '검증 가능한 사실 주장'만 선별. 우리 프로젝트의 "수치·스펙·단정만 트리거" 전략과 완벽히 일치하는 접근법
10년+ AI 개발 역사
2014년부터 자동화 팩트체킹 기술 개발 시작. 현재 세계 선도 수준의 클레임 감지 AI 보유. 우리가 참조할 수 있는 가장 성숙한 오픈소스 연구 기반
웹 스택 (추정)
Django/Wagtail CMS (Python) · Bootstrap 프론트엔드 · GTM 분석 · Mailchimp 이메일 · Schema.org 구조화 데이터

FullFact AI 접근법
📡
대규모 모니터링 — 수백만 문장/일 처리. 의회·SNS·뉴스 커버리지
🏷
Check-worthy 분류 — 검증 가능한 사실 주장 vs 의견 이분법
🔗
기존 팩트체크 매칭 — 기구축된 팩트체크 DB와 신규 클레임 유사도 비교
⏱
후처리 중심 — 실시간 아님. 전문가 검증 후 수시간~수일 내 퍼블리싱
우리 프로젝트 접근법
🎙
실시간 STT 스트림 — 인터뷰 음성 실시간 처리. 1:1 발화 컨텍스트
🔢
수치·스펙 특화 트리거 — Regex + GPT-4o-mini 2단계 필터. 비용 최적화
📄
이력서 RAG 대조 — 사전 업로드된 개인 서류와 발언 실시간 비교 (없는 기능)
⚡
실시간 ≤5초 — 면접관이 반박 질문을 즉시 활용 가능한 레이턴시 목표

🎯 핵심 차이점 요약
도메인 (Domain)
FullFact: 정치·정책·미디어 (공공 담론) 우리: IT 채용 면접 (B2B HR 버티컬)
처리 방식 (Timing)
FullFact: 후처리 (Post-hoc), 수시간~수일 우리: 실시간 (Real-time), ≤5초
사용자 (User)
FullFact: 일반 대중 + 저널리스트 우리: IT 기업 면접관 (B2B)
비즈니스 모델
FullFact: 비영리 자선단체 (기부 의존) 우리: B2B SaaS 구독 모델
검증 소스
FullFact: 공공 데이터·공식 통계·기사 우리: 이력서 RAG + 기술 공식 문서
🤝 공통점 (우리가 검증받는 부분)
✓
클레임 선별 트리거
FullFact도 모든 문장이 아닌 '체크워시 클레임'만 처리. 우리의 선별 트리거 설계 방향 검증됨
✓
Human-in-the-Loop 필수성
FullFact도 AI 단독 판정 없이 전문가 최종 승인. 우리도 면접관이 추천 질문 채택 여부 결정 (HITL)
✓
투명성 & 출처 명시
FullFact는 모든 팩트체크에 출처 링크 제공. 우리도 웹 팩트체크 결과에 출처 도메인 명시 필수
✓
다중 소스 교차검증
FullFact는 공식 통계 + 기존 팩트체크 크로스체크. 우리도 RAG + 웹 검색 병렬 실행
✓
신뢰 도메인 화이트리스트
FullFact는 공신력 있는 공식 통계만 참조. 우리도 redis.io, kubernetes.io 등 공식 문서 우선
📐 UX/UI 벤치마킹 포인트
① 팩트체크 결과의 명확한 레이블링
FullFact는 "True / False / Misleading / Unverifiable" 등 명확한 판정 레이블 사용. 우리 FactCheckCard에 "confirmed / disputed / uncertain" 3단계 레이블 + 색상 코딩 적용 완료 ✓
② 출처 투명성 (Source Attribution)
모든 팩트체크에 원본 출처 링크 제공. 우리 WebFactCheckResult에 출처 도메인 + URL + 발췌문 표시 → 면접관이 직접 검증 가능하게 해야 함
③ 정정 요청 메커니즘
FullFact는 Feedback & Corrections 페이지 운영. 우리도 면접관이 팩트체크 결과에 "이의 제기" 버튼으로 오류 신고할 수 있는 HITL 채널 필요
④ 정부 공약 트래커 → 이력서 약속 트래커
FullFact의 Government Tracker는 공약 이행 여부 추적. 우리의 이력서 항목 ↔ 실제 발언 대조는 동일한 개념의 HR 버전
⚙️ 기술 벤치마킹 포인트
① AI 벤치마크 → 내부 정확도 평가 체계
FullFact는 GPT/Claude 팩트체킹 정확도를 공개 평가. 우리도 Claim Detector F1-Score, RAG 정확도, 전체 판정 정확도를 내부 벤치마크로 관리해야 신뢰성 확보 가능
② 멀티모달 파이프라인
텍스트·오디오·영상 처리. 우리 현재 구조는 오디오 → STT → 텍스트. 이후 영상 분석(슬라이드 내용, 화이트보드) 확장 시 멀티모달로 진화 가능
③ 대규모 클레임 DB 구축
FullFact는 수천 건의 팩트체크 DB 보유 → 신규 클레임과 매칭. 우리도 세션이 쌓일수록 기술 벤치마크 클레임 DB(Redis TPS, K8s 버전 등) 누적 → 검색 속도·정확도 향상
④ 부분 자동화 + 인간 감수 원칙
10년 경험에서 나온 결론: "AI는 보조, 인간이 최종 판단". 우리 시스템도 추천 질문을 면접관이 채택/무시할 수 있는 HITL 구조로 이미 설계됨 ✓

① 시장 수요 검증
FullFact가 10년 이상 지속 성장 중이라는 것은 팩트체킹 수요가 실재함을 증명. 우리는 이를 HR 채용 버티컬로 특화
② 기술 접근법 검증
선별 트리거, HITL, 다중 소스 교차검증, 출처 투명성 — FullFact와 우리 설계가 동일한 원칙 공유. 올바른 방향임을 확인
③ 우리만의 차별화
